# 图表规范（Exhibit Grammar）

## 0. 先确认规范是不是最新版

本 skill 是 **v1.5（2026-11-23）**：v1.4 的全部规则，加三处改动：配色改为单一主色 `#0030B8` 加灰，不用橙色；网页图表加悬停数据（HR46）；自检脚本改成单独文件（附录 C）。另从 Knaflic《Storytelling with Data》补了「眼睛先落在哪」自检和 `big_number` 图型。

正本和更新记录在 GitHub：https://github.com/Liamfind/exhibit-grammar 。用户提到的规则和本 skill 不一致时，以仓库最新版为准，并提醒用户更新本 skill。

## 1. 出图流程（每张图都走一遍）

1. **先确认有结论句。** 手上没有一句可被证伪的结论，就先调用 deliverable-writing 写好（WR01、WR02），再回来出图。写不出结论就不画图。没装 deliverable-writing 时，最低要求：分析页标题是完整陈述句，建议页可用祈使句。
2. **判断要表达的关系**，再到本文附录 A「图型选择」选图型。关系分 11 类：量级比较、排名、构成、时间变化、分布、相关、偏离基准、流动与拆解、地理、分类对照，以及没有数据时用的 framework 示意图。
3. **套用下面的配色和字号**，不自己挑颜色。网页或 HTML 交付物，在 `<head>` 写 `<meta name="font-set" content="A">`（A/B/C/D 取 huashu-design 第 0 节的字体池，连续两份对外页面不同套）；页面开头用了 KPI 四格条的，再写 `<meta name="opening" content="kpi-strip">`。
4. **标注。** 能直接标就不用图例（HR15）。只标要讲的那几个数。网页或 HTML 交付物，**第一稿就带悬停，不等用户提**：其余的数放进悬停，每个条、柱、点、格子写 `data-tip`，页面末尾放本 skill 的 `assets/chart-hover.js`（HR46）。结论要用的数仍直接标在图上。
5. **自检。** 先做「眼睛先落在哪」测试：移开视线再看回来，第一眼落在哪；不是要讲的那一项，就调高亮的明度、粗细或位置，不加色相（HR14，R10）。再逐条过一遍附录 B「硬规则」里的 blocker。图是 SVG 的（独立 .svg 文件，或网页里内嵌的 SVG），用本 skill 文件夹里的脚本查交付的那个文件：`python3 <本 skill 文件夹>/scripts/check_svg.py 文件 [显示宽度] [页面底色]`。只有输出「通过」才算过。输出「未检查」时，把写法改成脚本认得的，或在浏览器里人工核对，并在交付说明里写明哪几处是人工核对的。网页文件还会查悬停（HR46）：数据图没写悬停数据、或页面里没有显示脚本，都判不合格；framework 示意图在 `<svg>` 上写 `data-kind="framework"` 就不查。

## 2. 一张 exhibit 的结构（从上到下）

- **结论标题**：一句话，数字必须能从图里直接读出来。
- **口径行**：指标名、范围、时间、单位，只描述口径，不重复结论；金额跨度超过 3 年要写明名义价还是不变价（HR35）；调研题写成题干模板「% 认为 __ 的受访者」，画出的选项加粗（deliverable-writing WR04、WR05）。
- **图**
- **Note**：口径定义、计量日期；没画出来的选项和无回答、合并过的档位、入选规则、只适用于部分行的人群限定；以及「这张图不能说明什么」（deliverable-writing WR09–WR11）。
- **Source**：出处、机构、统计期间。第三方数据加检索日期（HR04）。

没有真实数据，就标成 framework 示意图：不编数字，不给数据 Source 行，不给精确刻度；可写一行「依据：…，非调研数据」（HR05）。示意数据必须写明「示意数据」。

## 3. 配色：高亮加灰化两色制

| 用途 | 色值 |
|---|---|
| 主色：只给要讲的那一项 | `#0030B8`（默认品牌蓝，对白 9.92:1） |
| 灰 1 到 5（深到浅） | `#6B7280` `#868E9A` `#D2D7DE` `#E8EBEF` `#F3F4F6` |
| 提示黄：白底上的文字 | `#8A6100`（5.54:1） |
| 提示黄：只当标签底色，上面写 `#0F1419` | `#F2B705` |
| 主文字 | `#0F1419` |
| 次要文字 | `#5B6370` |
| 顺序色阶（浅到深） | `#EFF2FB` `#CED7F1` `#97ABE2` `#476ACC` `#0030B8` |
| 页面底色 | `#F6F6F6`；图底白色 |

- 其他系列一律用灰，不再加第二个蓝。两个肉眼分不清的颜色（ΔE < 20）不能当作两个系列。
- 浅蓝 `#97ABE2` 只在有顺序的量表里当第二档用，比如同意程度。色阶第 4 档 `#476ACC` 上写白字（4.99:1），前 3 档上写 `#0F1419`。
- **灰色图形和黄色的对比度（HR34）**：承载数据的灰化条、线、点、面只用灰 1 `#6B7280`（对白 4.83:1）或灰 2 `#868E9A`（3.31:1），对白底 ≥3:1，不加透明度（灰 2 加 0.9 透明度就掉到 2.87:1）。旧灰 2 `#A8B0BA` 只有 2.19:1，已停用。灰 3 到灰 5 只做网格、底纹、分隔和空槽。黄色不进图形配色：白底黄字用 `#8A6100`（5.54:1）；亮黄 `#F2B705` 只当标签底色，上面写 `#0F1419`（10.18:1）。深色底上灰 2 对 `#0F1419` 是 5.60:1 照用，黄字改用 `#F2B705`。直接标了数也不豁免。
- 有顺序的数据用单色明度阶，有中点的数据（涨跌）用双向色阶，无序类别才用不同色相（R5）。
- 颜色不能是传达信息的唯一手段（HR10）。转灰度后结论还看得出来，才算合格（HR22）。
- 面积比例参考 90/10：中性色约 90%，主色约 10%。要强调的不另加颜色，用加粗或直接标注。
- **已停用的颜色**：`#003088`、橙色 `#FF3100` 和橙色文字 `#C42800`（v1.4 及更早版本用过）。全页搜一遍，不出现这三个值。
- 主色 `#0030B8` 是默认值，用在自家出面的交付物上；自家有品牌规范的，按品牌规范的主色换。交付物按客户品牌做时，只把主色换成客户主色。客户主色是浅色（亮黄、浅绿这类），对白底不到 3:1（HR11）时不要硬用：要讲的那一项改用 `#0F1419` 加粗、其余用灰，或换一个和客户品牌色不冲突的颜色（R10）。色阶按主色占 6%、19%、41%、72%、100% 从客户主色混白重算（第 4 档上白字不到 4.5:1 就再加深），灰阶和其余规则不变。

## 4. 字号与对比度

- 图内文字**渲染后 ≥11px**，数据标签约 12–13px，要讲的那个数加粗。
- **整页 UI 文字同样 ≥11px**：网页、品牌站 Demo、看板里的导航、按钮、标签、脚注、页脚、徽标文字都算，不只图内文字。正文 ≥14px。交付前对整页跑一遍字号检查（可在浏览器里遍历所有可见文字元素取 computed font-size），有 <11px 的就改。
- SVG 画布宽 360 时，标签 `font-size` 取 11.5，数值取 12.5，强调值取 13.5。画布更宽，就按显示宽度等比放大。
- 每个文字标签对它背后的底色对比度 **≥4.5:1**（HR11）。深色块上用白字，浅色块上用 `#0F1419`。不能在浅灰块上写白字。
- 数字用等宽数字（`font-variant-numeric: tabular-nums`）。
- **调研子群样本门槛（HR32）**：有效样本 <100 画 95% 误差线并写 n；原始 <100 或有效 <50 不出数；差异结论看显著性检验，两组对比加「差值」列。详见附录 B · HR32。
- **人口学交叉条形图**（调研交叉表）：总计行置顶，其余按维度分块（性别、年龄、城市级别、收入），块标题用小号灰字，块内保持维度原顺序；最多 21 行，超了拆页。
- **只画部分档位的堆叠条**（例如只画「非常」和「比较」）：条端标 NET 合计，NET 用未四舍五入的值相加。
- **趋势缺期**：某期没问到或口径不可比，该点留「—」，不画 0、不跨期连线，Note 写原因（HR17）。
- **口径与写法类规则（详见附录 B）**：跨年金额写名义价或不变价（HR35）；同一批对象画上升、不变、下降三段（HR36）；情景命名、预测点线、Note 写「情景不代表概率」（HR37）；测算写区间或「~」，Note 写「量级估算，非置信区间」（HR38）；倍数给两边原值（HR39）；换窗口差 ≥10 个点就并列窗口（HR40）；多选、累计档、分母不同的数不叠加（HR41）；变化写个百分点并给两端，↑/= 写阈值（HR42）；不画平滑曲线（HR43）；高亮框、填充带、括号、箭头都要说明（HR44）；爬取、众包名单的计数写「≥」并写覆盖率（HR45）；网页图表第一稿就给每个图元加悬停数据，内容是「系列｜时间｜数值和单位｜口径」，和图上标签同一份数据（HR46）。
- **跨图一致**：同一分组全套同色、同顺序，量表方向统一，小数位一致（HR33）。
- 要比较「实际 vs 各自的应有份额」（GMV 占比 vs 流量占比、样本构成 vs 人口构成），用基准点条形图：条是实际，空心圈是基准，右侧单列写差值。
- 轴标签一律水平（HR19）。条形图和面积图的数值轴从 0 开始（HR08）。不用双 Y 轴，量纲不同就拆成并排小图（HR07）。

## 5. 字体（网页或 HTML 交付物）

页面字体按 huashu-design 第 0 节的 4 套字体池轮换，连续两份对外页面不用同一套；图内文字跟随页面正文字体。下面这组是池里的 A 套：标题和结论标题用 Noto Serif SC，正文用 Noto Sans SC，代码和口径用 IBM Plex Mono。PPT 里没有这些字体时，用思源宋体加思源黑体。

## 6. 最常犯的 5 个错

1. 分量 ≥5 还用饼图：改用 100% 堆叠柱，直接标数。
2. 量纲不同开双 Y 轴：改用小倍数（并排小图）。
3. 要讲「差异大」却画均值柱：改用蜂群图或箱线图。
4. 要讲「差距」却只画实际值：改用哑铃图。
5. 把分类标签塞进热力图：改用分类矩阵，字母留在格子里。

## 附录 A · 图型选择（v1.5）
每个图型给出：用于什么场景、绝不能怎么用、标注纪律。

### 量级比较（magnitude）：比大小。通常是计数型数字（人数、金额、件数），不是算出来的比率。
- **水平条形图** `bar`：用于 类别标签长、类别数 4–12、要比大小。绝不：轴不从 0 起（条形图轴必须从 0，source B10）；不排序又不是天然有序（读者无法扫描）。标注：条端标数值或轴上标，二选一不并存；同一系列单色，只把要讲的那根上高亮色
- **垂直柱状图** `column`：用于 时点离散且 ≤8 个；或类别名短。绝不：超过 8 个时点还用柱（改用线）；柱间距大于柱宽（应约为柱宽的一半，source B10）。标注：只标要讲的那几根的数值；负值向下延伸并在下方标负号
- **成对条形（左右镜像）** `paired_bar`：用于 同一批对象的两个指标要并排看顺序是否同向。绝不：两侧用不同量纲却不标单位；对象数 >15。标注：中轴放对象名；两侧各自标单位
- **变宽柱（Marimekko）** `marimekko`：用于 要同时表达『跑得多快』和『块头多大』。绝不：宽度和高度用同一量纲（那就是普通柱）；格子超过 12 个。标注：画一条全局均值水平参考线并标注；小块用引线外挂标签；被剔除/需特别说明的面积用虚线框圈出
- **棒棒糖图** `lollipop`：用于 项目数 12–40，条形图太密。绝不：项目数 <8（直接用条形）；圆头大小无含义还画成不同大小。标注：画一条 Average 水平线并在左端标斜体 Average；负值区整片打浅灰底；右上角给空心圆尺寸图例
- **子弹图** `bullet`：用于 实际值 vs 目标值 vs 区间基准。绝不：没画目标标记（那就退化成普通条）。标注：目标用竖线标记而非另一根条；背景分档用同色系明度阶
- **估算区间条** `range_estimate`：用于 自下而上测算的市场规模、成本、潜在收入，输入假设本身是一个范围（渗透率、客单价、转化率），论点是量级和谁大谁小。绝不：调研抽样得到的估计（用置信区间条形图，HR32）；时间序列的预测（用扇形预测图或情景折线，HR37）；上下限相差 3 倍以上（先收窄假设，或只写量级）。标注：两端标上下限，中值用细竖线或「~」；写「区间」不写 ±；Note 写区间来自哪个假设，并写明「量级估算，非置信区间」（HR38）
- **比例符号（气泡）** `proportional_symbol`：用于 量级差异极大（跨数量级），或需叠加在地图上。绝不：用直径而非面积编码（会夸大 π 倍）；要求读者精确比较（面积比较误差大）。标注：必须给嵌套圆尺寸图例；标签上下交错用细引线连接避免重叠
- **图形化计数（Isotype）** `isotype`：用于 面向非专业受众讲『多少个』，数值小且是整数。绝不：半个图标表示小数；数值 >50（数不过来）。标注：图例必须说明一个图标=多少
- **人口学交叉条形图** `banner_bar`：用于 一个指标在总体与多个人口学子群（性别、年龄、城市级别、收入）上的值，也就是调研交叉表。绝不：块内按数值重排，打乱维度原有顺序（年龄、城市级别本身有序）；超过 21 行（拆成两页）；子群有效样本 <100 却不画误差线（HR32）。标注：总计行置顶，与分块之间加一条细线；块标题用小号灰字，不进坐标轴；只把要讲的那一行上主色，其余灰
- **条形表** `bar_table`：用于 多个项目各有一个值和一个「比上期」变化，读者既要扫数也要看变化；行可按结论句分组。绝不：超过 12 行；变化列不写单位或阈值（HR42）；分组后又按数值重排。标注：短条只给要讲的那一行上主色，其余灰 2；变化列写「+11 个点」，小于阈值写「=」，阈值写 Note；组标题用小号灰字
- **大数字加一句话** `big_number`：用于 只有 1–2 个数要讲，画成两根柱反而削弱了数本身。绝不：数超过 2 个（改条形图）；要读者自己比大小或看趋势；为了醒目只留一个变化率、丢掉两边原值（HR39、HR42）。标注：数字放大加粗，同一句话写比较对象和结论（书中的例子：2012 年有全职妈妈在家的孩子占 20%，1970 年是 41%）；指标、范围、时间写在数字旁边或口径行；有真实数据照写 Source（HR04）；网页里直接用页面文字排，不画成 SVG，也就不需要悬停（R10 · Knaflic 第 2 章 Simple text）

### 排名（ranking）：某项在有序列表中的位置，比它的绝对值更重要。
- **排序条形图** `ordered_bar`：用于 名次比数值重要，类别 ≤12。绝不：按字母序或按原表顺序排（那是 magnitude 不是 ranking）。标注：大胆高亮你要讲的那一项，其余灰化（FT 类别定义明文鼓励）
- **排序柱状图** `ordered_column`：用于 类别名短且需要垂直版面。绝不：类别名需要旋转才放得下（改横向）。标注：轴标签一律水平排版（source B5）
- **点带图** `dot_strip`：用于 只要位置不要长度；或要同时看排名和分布。绝不：点重叠严重却不做抖动（改 beeswarm）。标注：只对极端项和知名项挂标签
- **斜率图** `slope`：用于 只有起止两个时点，且要看谁涨谁跌、名次是否换位。绝不：中间其实有数据却只取两点（丢失波动）；线条超过 10 条（成毛线团）。标注：两端直接标名称与数值，不用图例；只给要讲的 1–2 条上色，其余灰化
- **名次线图** `bump`：用于 多期名次变化。绝不：用它表达数值差距（名次轴等距，数值不等距）。标注：两端标名称；只高亮 1–2 条

### 构成（part_to_whole）：各分量如何组成一个整体。
- **堆叠条形图** `stacked_bar`：用于 构成分量 ≤4，且要比较多个整体。绝不：分量 >4（每根柱最多 4 段，source B5）；把最重要的分量放中间。标注：段内标绝对值、段外标百分比，两个量纲物理分离；图例顺序必须与图内堆叠顺序一致（source B5）；只画部分档位时，条端标 NET 合计，用未四舍五入的值相加（R8）
- **堆叠柱状图** `stacked_column`：用于 时点离散且要看结构漂移。绝不：同上；另：时点 >8 改用 stacked_area。标注：柱顶标合计；分项标签用引线挂外侧，不塞进窄柱
- **100% 堆叠柱** `pct100_column`：用于 只关心占比、不关心总量；或要比较多个整体的结构。绝不：总量差异本身也是论点却用了它（那要 marimekko）；段数 >4。标注：段与段之间用虚线连接对应色块（share cascade），放大的斜率本身就是论点
- **面积比例韦恩图** `euler`：用于 2–3 个集合的重合（受众、平台、渠道），论点是同时满足几项的占多少。绝不：集合 >3（改条形列交集）；等大示意圆上标数；只标合计或只标独占块。标注：灰框代表全集，「都不属于」写在里面；每块写独占份额，各集合合计写在圆外；口径块加粗并写加总（「≥2 项 = 13+7+2+1」）（R9 · MGI 2026-11-12 图 1）
- **饼图** `pie`：用于 分量 2–4，且只有一个整体，且『占一半以上/不到一半』这种粗判断就够了。绝不：分量 ≥5（ONS 理想 3–4、不超过 6；Urban <5）；两个饼并排做对比（改 100% 堆叠柱）；环形图叠数字当 KPI 装饰。标注：类别名与数值直接标在扇区上，不用图例（source B6）
- **环形图** `donut`：用于 与 pie 相同，且中心需要放合计数字。绝不：分量 ≥5；中心不放数字（那不如用饼）。标注：同 pie
- **树状图** `treemap`：用于 构成有层级，且要在同一画布表达总盘子/一级占比/二级占比三层。绝不：无层级（用 100% 堆叠柱更好读）；要求精确比较相近的两块。标注：一级类别标题连同金额排在图外四周；极小块用直角折线引线外挂并标 <1
- **瀑布图** `waterfall`：用于 把一个净变化拆成驱动项，且首尾要能勾稽。绝不：分项 >8 不归组；轴截断却不做补偿。标注：段内嵌 ▲/▼ 方向三角 + 带符号数值；需要跨段归组时用顶部方括号 + 概念名；轴截断时右侧放一个从 0 起的迷你全量程缩略图并标『Detail shown』

### 时间变化（change_over_time）：随时间推移的变化。FT 中收录图形最多的一类（14 种）。
- **折线图** `line`：用于 连续多期、看趋势与波动。绝不：双 Y 轴（除单位换算与 Pareto 外应避免，source B10）；线条 >5–6 条（改 small multiples 或 focus_line）；把有缺口的时间序列画成连续线。标注：线末端直接挂系列名，不用图例（source B5）；预测段改点线并加竖虚线标『今天』；y 轴不从 0 时若趋势是 message 可接受，但差值是 message 时必须标注；直线段连实测点，不画平滑曲线（HR43）；要讲背景时，事件最多 3 个，用「日期 + 一词」细竖线，阶段用灰底带并写阶段名
- **面积图** `area`：用于 单一序列且要强调累积量。绝不：多序列半透明叠加（互相遮挡，读不出任何一条）；轴不从 0（面积编码必须从 0）。标注：轴必须从 0
- **堆叠面积图** `stacked_area`：用于 时点多（>8）且要看结构随时间漂移。绝不：分层 >4；读者需要精确读出中间层的值（只有最底层可精确读）。标注：用引线把色带引到右侧标签，取消图例
- **小倍数（并排小图）** `small_multiples`：用于 多个指标量纲不同，或多个主体同结构对比。绝不：小图之间不共享坐标范围却不标注；小图 >12 个。标注：各自独立 y 轴时必须每张都标范围；统一用『×倍数』表达变化幅度以便横向可比；共用一条 Source 行
- **焦点折线图** `focus_line`：用于 多条序列但只讲其中 1–2 条。绝不：给每条线一个颜色（读者以为每种颜色都有语义）。标注：两色制：高亮色 + 灰化色（如 AF 的 #12436D + #BFBFBF）；高亮线画粗一点
- **扇形预测图** `fan_chart`：用于 有预测区间且不确定性本身是 message。绝不：没有真实区间估计却画扇形（编造不确定性）。标注：标明区间含义（如 80% / 95%）
- **日历热力图** `calendar_heatmap`：用于 高频周期性数据（日级、小时级）。绝不：数据不足一个完整周期。标注：色阶图例只做定序不给精确刻度
- **连接散点图** `connected_scatter`：用于 两个变量的关系如何随时间演变。绝不：不标起点终点与方向箭头（读者不知道往哪走）；时点 >15（成乱线）。标注：起点终点必须标年份并给方向箭头

### 分布（distribution）：数据集中的取值及其出现频次；分布的形状与偏度本身就是论点。
- **直方图** `histogram`：用于 样本量大，要看取值集中在哪个区间。绝不：分箱宽度不等却不标注；柱间留缝（直方图应无缝或紧邻，与柱状图区分）。标注：标注分箱宽度与样本量 n
- **箱线图** `boxplot`：用于 比较多组分布的中位数与离散度。绝不：面向非分析型受众直接用（需要解释箱须含义）；样本量 <10（改 dot strip 显示原始点）。标注：标注 n；必要时叠加原始点
- **置信区间条形图** `ci_bar`：用于 调研子群比较，且至少一个子群的有效样本量 <100（按加权损失折算后的样本量）。绝不：原始样本 <100 或有效样本 <50 的子群：不出数，留空并写「样本不足，不显示」；所有子群有效样本都 ≥100 时为每根条都加误差线（徒增噪声）。标注：误差线 = 95% 置信区间，在图脚写明；每行右侧写 n=有效样本量；两组对比加差值列：显著加粗，不显著写「--」；Note 写明误差线只代表抽样误差
- **蜂群图** `beeswarm`：用于 要展示离散度而非平均值，且每个点都值得保留。绝不：点数 >300（改 histogram）；不给参考线（读者无基准）。标注：用空心菱形叠加该组均值；轴上加一对反向箭头做语义标尺；只对极端/知名个体挂名称标签
- **条码图** `barcode`：用于 小样本、要看每个值的位置且空间极窄。绝不：重叠严重（改 beeswarm）。标注：叠加均值/中位数标记
- **累积曲线（Pareto/长尾）** `cumulative_curve`：用于 要说『头部集中』或『长尾不均』。绝不：不排序；不标 80% 或 100% 参考线。标注：顶部 100% 处加水平点线；最宽的几段把标签写进色块内部，窄段用引线外挂；右端用方括号标注长尾规模
- **人口金字塔** `population_pyramid`：用于 按两个互斥组别的年龄/分档分布对照。绝不：组别不互斥。标注：中轴放分档标签
- **小提琴图** `violin`：用于 分布形状（多峰）本身是论点且受众是分析型。绝不：面向客户高管使用（认知成本过高）。标注：叠加中位数标记

### 相关（correlation）：两个及以上变量之间的关系。FT 在类别定义里直接写了叙事红线：除非你明确说明，多数读者会默认你展示的是因果。
- **散点图** `scatter`：用于 两个连续变量的关系，样本 >15。绝不：在标题里暗示因果而无因果证据；样本 <10（改 paired bar）。标注：标注全样本均值并画十字点线；点直接挂对象名，不用图例；有拟合线时必须说明拟合方法与 R²
- **气泡图** `bubble`：用于 散点 + 第三个量级维度。绝不：用直径编码；第四维再上色相（超载）。标注：必须给尺寸图例
- **热力表** `xy_heatmap`：用于 多维度 × 多主体，要做模式识别而非精确读数。绝不：用它做精确比较；用多色相而非单色明度阶（除非是发散型）。标注：色阶图例做成离散格渐变条，两端写 Lowest/Highest，刻意不给数值刻度；行分组用小标题 + 组内均值行；精确数值另挂在右侧独立列，与热力区用细线分隔
- **四象限散点 / 2×2 矩阵** `quadrant_scatter`：用于 两个二分维度的交叉分类，读者需要『落在哪个格子』。绝不：象限分界线随意划却不说明依据；只有 2×2 框没有数据（那是 framework 不是 exhibit，必须标 state=framework）；把 2×2 说成麦肯锡的招牌框架（出处是 BCG）。标注：四角放微型符号图例说明该象限含义；0 轴用点线十字；需要表达每格价值占比时另配一个 2×2 面积矩阵——散点本身表达不了占比

### 偏离基准（deviation）：相对某个固定参照点的正负变化。参照点通常是 0，也可以是目标值或长期均值。
- **发散条形图** `diverging_bar`：用于 正负跨零轴的排名。绝不：零轴不居中或不画出；正负用同一颜色。标注：左轴写语义方向（如『更多净出口 / 更多净进口』）而非只写数字，把符号翻译成业务含义；第二量纲（变化幅度%）外置成轴下一排圆形药丸
- **基准点条形图** `benchmark_bar`：用于 每一行都有自己的应有份额或参照值（GMV 占比 vs 流量占比、样本构成 vs 人口构成），论点是谁高于、谁低于自己的基准。绝不：所有行共用同一个基准值（那就画一条竖向参考线）；基准与实际不是同一口径或同一单位。标注：基准用空心圈，不用第二根条；右侧单列写差值，正负号写全；图脚写明圈代表什么、口径来自哪里
- **发散堆叠条形图** `diverging_stacked_bar`：用于 李克特量表类数据（非常同意→非常不同意）。绝不：中性项被拆到两边；档位 >7。标注：中性档单独居中或单列；两端各标 NET 合计（如「NET 同意 62」），用未四舍五入的值相加（R8）
- **脊柱图** `spine`：用于 二分构成（是/否）在多个主体间的对比。绝不：超过两个分类。标注：中轴标主体名
- **盈亏填充折线** `surplus_deficit_line`：用于 时间序列相对某基准的正负区间。绝不：基准线不画出。标注：基准线用点线并标注它是什么
- **哑铃 / 箭头点图** `dumbbell`：用于 两个时点或『实际 vs 应有』的缺口，缺口本身是论点。绝不：不给方向箭头（读者不知道谁在前）；行数 >15。标注：图例本身画成一个微型示意图（起点—终点—箭头—目标点的完整语法）；对已达标的行加文字注释；画竖虚线标目标值/均值并写出标签

### 流动与拆解（flow）：两个或多个状态之间流动的量或强度；也包括把一个净变化拆成驱动项。
- **桑基图** `sankey`：用于 要保留『从哪到哪』的配对关系与流量大小。绝不：节点 >12（成面条）；只有一层流转（用 funnel 或 waterfall）。标注：节点名直接标在节点上
- **弦图** `chord`：用于 双向流动、对象集合固定且 ≤12。绝不：对象 >12；流动是单向的（用 sankey）。标注：外圈标对象名
- **网络流向图** `network_flow`：用于 方向与配对关系是核心信息，且节点有地理或类别语义。绝不：不给图例说明三种编码分别是什么。标注：两个时期各占一整页做 before/after，第二页省略图例只保留时期大字
- **漏斗图** `funnel`：用于 单向、阶段固定、逐级递减的转化链。绝不：阶段之间不是真正的子集关系（那是伪漏斗）；各级不标转化率只标绝对值。标注：每级之间标转化率（%）和流失绝对值；阶段名固定，渠道/动作作为可替换 Slot

### 地理（spatial）：地理位置或空间格局。FT 设了准入门槛：除定位图外，只有当精确位置或地理格局比其它任何东西都更重要时才用地图。
- **分级填色地图** `choropleth`：用于 指标是比率/密度，且地理格局比其它任何东西都更重要。绝不：用它画计数（大面积地区被夸大，应改比例符号图）；分级数 >7 或 <4。标注：分级 5–7 级；单色明度阶；必须标明是比率还是计数
- **比例符号地图** `proportional_symbol_map`：用于 指标是计数/量级且需要地理定位。绝不：符号重叠严重不做处理。标注：嵌套圆尺寸图例
- **流向地图** `flow_map`：用于 起点终点都有地理意义。绝不：线路交叉过多。标注：边宽=流量，箭头=方向，均需图例
- **点密度地图** `dot_density`：用于 要表达绝对分布密度而非行政区聚合值。绝不：一个点代表多少不标注。标注：必须标注一个点 = 多少单位
- **变形地图** `cartogram`：用于 行政区面积会严重误导（如按人口而非国土面积）。绝不：受众不熟悉该地区形状（认不出来）。标注：附一张常规地图做对照

### 分类对照（nominal）：格内或轴上是分类标签（资格 / 状态 / 类型 / 语义领地），不是可测量的数值。读者要做的是模式识别——「哪一格是空的」「哪一行整行都缺证据」——而不是读数或比大小。
- **分类矩阵** `nominal_matrix`：用于 两个维度交叉，格内是分类标签（资格 / 类型 / 适用性），且每格标签有证据支撑。绝不：格内其实是可测量数值（那是 xy_heatmap，属 correlation）；把「无可比证据」和「值为 0」用同一种视觉表示；无序标签却用单色明度阶，暗示了不存在的等级。标注：图例必须逐类说明每个标签的含义与取得方式（如 Q=方向性定量 / L=有日期的定性审计 / P=当前无可比证据）；「无可比证据」与「不适用」必须是两个可区分的视觉，且都不得读成 0；给 Source 行，并写明标签的判定时点
- **状态网格** `status_grid`：用于 N 个对象 × 若干阶段/条件，每格是当前状态，且「还差什么」是论点。绝不：把离散状态画成进度百分比；状态档位 >5（读者记不住图例）。标注：状态档位固定且全图一致；每格可加一行小字写「还需要什么证据」——这常常比状态本身更有用
- **语义领地图** `territory_map`：用于 竞品/主张在两个语义维度上的占位，轴不可测量，位置只表示分组不表示坐标。绝不：给轴标数字刻度；让读者比较两点之间的「距离」；轴其实可测量却用它（那该用 quadrant_scatter 并给来源）。标注：轴只写语义端点词，不给刻度；明确标注这是基于什么证据的判读（如「官网语言审计，2026-08-19」）；空白地带若是论点，要显式圈出来并命名

### framework 示意图（framework）：framework 页不是「没做完的 exhibit」，是一类合法产出——当 conclusion_type 属于 method / scope / decision_gate / next_step 时它本来就该是 framework。但 form 必须落在本词表内，不许自造；且一律不给数据 Source 行、不给精确刻度、不出现看似实测的数字，可写一行「依据」（HR05）。实证来源：一份 37 页的客户提案 deck 里 24 页的 conclusion_type 属于这四类，用受控 framework 词表后这 24 页收敛到 8 个 form。
- `framework:divider` 章节分隔：切换大板块、重置注意力
- `framework:timeline` 时间轴 / 排期：阶段、里程碑、闸门的先后顺序是论点
- `framework:process` 流程 / 链路：步骤之间是因果或依赖关系，且顺序不可换
- `framework:matrix` 矩阵 / 网格：两个维度交叉分类，或多个并列项按同一组字段对照
- `framework:hierarchy` 层级 / 信息屋：上位主张 → 下位支撑的从属关系
- `framework:ladder` 阶梯 / 门槛链：必须逐级通过的证据链或审批链
- `framework:tree` 决策树：分支条件与各分支后果
- `framework:stack` 分层堆栈：交付物或能力按层级堆叠，下层支撑上层

- **HR01、HR02、HR03、HR23、HR24、HR28** 已迁到写作 skill deliverable-writing（WR01、WR02、WR04–05、WR06、WR08–11、WR07），编号保留以免旧引用失效。
- **HR04** [blocker] 含真实数据的图必须有 Source 行，格式为『来源出版物/调查 + 机构 + 统计期间或检索时点』。第三方数据必须带 accessed 日期。外部源与自家分析分开署名，自有模型出数时点名该模型（例：『…；XX 公司达人 ROI 模型；XX 公司分析』）。
- **HR05** [blocker] 没有数据就标 state=framework，不许编数字，也不许让示意图看起来像实测图（不给数据 Source 行、不给精确刻度）。可写一行「依据：12 场高管访谈归纳，非调研数据」说明框架从哪来（访谈、案例或分析方法），不写成「Source:」。

- **HR07** [blocker] 禁止双 Y 轴。量纲不同就用 small multiples。例外仅两种：单位换算（同一量的两种单位）与 Pareto 图。（R2 · R7）
- **HR08** [blocker] 条形图与面积图的数值轴必须从 0。折线图与散点图不必。（R2 · R7）

- **HR36** [warn] 同一批对象前后两期的变化：追踪样本、老客复购、同一批渠道或门店前后两期比较时，不能只给净差。要画三段：上升、不变、下降的占比（100% 堆叠条或三段条），净差写在条尾当注释。上升和下降都不小、净差却很小时，结论写「多少人变了」，不写「几乎没变」。三段四舍五入合计不等于 100% 时，Note 写明。不同的两批对象（两次独立抽样）不适用本条，按 HR32 看差值显著性。（R8 · 皮尤 2026-10-28 追踪样本快讯）

- **HR38** [warn] 区间估算（非置信区间）：自下而上测算的市场规模、成本、潜在收入，假设本身是一个范围时，写成区间（「3–5 万亿」）或量级（「~4 万亿」「~300」），不写「4.27 万亿」这类比假设更精确的点值。画图用估算区间条：两端标上下限，中值用细竖线或「~」，不画误差线，不写 ±。Note 写「量级估算，非置信区间」和区间来自哪个假设。调研抽样的不确定性用置信区间条形图（HR32），时间序列的预测用扇形预测图或 HR37。（R9 · BCG The Future of Digital Assets 2026-05 · 麦肯锡 The State of Fashion 2026 · a16z）
- **HR39** [warn] 倍数写法：写「3.6×」「是……的 3.6 倍」时，同一处给出两边原值和比较对象（「3.6×（7.2% vs 2.0%）」）。不写反向倍数（「低 9 倍」「少 9 倍」），改写两边比例（「流失率 2% vs 18%」）。任一边基数 <1% 或绝对量很小时不写倍数，写原值和差值。倍数的取整按 HR18。（R9 · BCG GenAI Potential to Profit in Banking 2026-01 · BCG AI Radar 2026 · 麦肯锡 Global Energy Perspective 2026）
- **HR40** [warn] 窗口敏感：同一个结论数随时间窗或归因窗变化（测算 35/50/75 年，ROAS 7/28/90 天归因，留存 30/90 天），不同窗口结果相差 ≥10 个百分点时，并列 2–3 个窗口，默认口径上主色，其余灰 2 #868E9A（HR34）；标题写区间（「补上 58%–82%，看算多少年」），不只挑一个好看的数。差 <10 个点只报默认窗口，Note 写其余窗口的值。10 个点的门槛是 2026-11-09 扫描时定的，可按业务调。与 HR30（Note 时间窗与轴一致）、HR37（情景假设不同）分开：本条是假设相同、只换窗口长度。（R4 · PolicyViz 2026-11-02：取消社保税封顶，35/50/75 年补上 82%/68%/58%）
- **HR41** [warn] 不可加总：多选题（每人可选多项）、累计档（「至少中等」包含「广泛」）、各项分母不同的数，不画堆叠柱、饼图或 100% 条，也不写合计，改独立横条按值排序。Note 写原因：「多选，合计 >100%」「累计口径，不相加」「各项分母不同」。单选题四舍五入不等于 100% 按 HR36 写 Note。（R9 · 德勤 State of AI in the Enterprise 2026-10 图 3/5/9 · 奥纬论坛 CEO Survey 2026 图 2/3）

- **HR44** [warn] 每个非数据标记都要说明：高亮框、填充带、括号、箭头、阴影区写进图例、直接标注或 Note；没有编码的装饰（同心圆、渐变、插画底纹）不加。框线和虚线的含义按 HR17，不另起约定。与 HR30 互为反向：图上有的元素，图例或 Note 要说。（R9 · 德勤 CFO Signals 2026 Q1 图 2 · 奥纬 300k Voices、CEO Agenda 2026）

- **HR46** [blocker] 网页图表的悬停数据，第一稿就带，不等用户提：只适用于网页、HTML 和 Artifact 交付物；PPT、PDF、图片不适用，也不因此把静态图改成交互图（静态还是交互是门派差异，不是对错）。每张数据图里，读者可能想查准确值的每个图元（条、柱、点、格子、线上的每个时点）都写 `data-tip`，鼠标悬停、手指点按、键盘 Tab 到它时显示。内容按固定顺序用全角竖线隔开：「系列或类别｜时间或期间｜数值和单位｜口径」，口径写明是披露数、后台数、估算还是示意数据，例：`data-tip="人力｜2025 年｜56.5%（占净收入）｜年报附注"`。悬停是补充，不替代直接标注：结论标题和正文要用的数仍直接标在图上，因为截图、PDF、打印和投屏都没有悬停。悬停里的数和图上标签、正文用同一份数据、同样的取整（HR18），不从条长或像素位置反推；数据里没有的值不写。细线和小点不好点中，把一行或一列包进 `<g data-tip="…">`，里面先画一条整行宽的透明命中带（`<rect … fill="transparent"/>`），高度取整个行距，行与行之间不留缝，尽量让手机上每行有 24px 高；行太密做不到时，提示框第一行就是这一行的名字，点错了看得出来。显示脚本用 `assets/chart-hover.js`，原样放进页面末尾的 `<script>`，不引图表库；图是图表库画的、库自带提示框时，内容照这四项写。framework 示意图不加，在它的 `<svg>` 上写 `data-kind="framework"`；没有文字的图标不加。（WCAG 2.2 · 1.4.13 悬停内容可用 Esc 关闭 / 2.1.1 键盘可达 / 2.5.8 目标尺寸）

## 附录 C · 自检脚本和悬停脚本（随本 skill 一起分发）

- `scripts/check_svg.py`：只用 Python 标准库。用法 `python3 scripts/check_svg.py 图.svg|页面.html [显示宽度px，默认 360] [页面底色，默认 #FFFFFF]`。查渲染后字号 ≥11px、文字对背后底色 ≥4.5:1、两个彩色是否肉眼分不清（ΔE<20）。三种结果：通过（退出码 0）、不合格（1）、未检查（2，查不了的写法逐条列出，不算通过）。网页文件还查悬停数据（HR46），数据图缺了判不合格。认得和查不了的写法见脚本开头的说明。一页里的图显示宽度不一样时，按最窄的那张跑。
- `assets/chart-hover.js`：HR46 的显示脚本，约 40 行，不需要图表库。原样放进页面末尾的 `<script>`；图上的元素写 `data-tip="系列｜时间｜数值和单位｜口径"`。鼠标悬停、手指点按、键盘 Tab 都会显示；点空白处或按 Esc 关闭。
